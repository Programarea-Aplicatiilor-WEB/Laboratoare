Instrucțiuni de lucru și de predare

Programarea aplicațiilor web · Seria MIAI · cum îți publici și cum predai lucrările de laborator

Lucrările de laborator nu se trimit pe e-mail și nu se predau pe hârtie: le publici pe internet, la o adresă proprie, și le predai printr-o cerere trimisă către repository-ul laboratorului. Tot ce urmează se face din browser, fără să instalezi nimic.

cont GitHub→ fork→ încarci fișierele→ pornești pagina→ pull request

Pasul 1 — Contul de GitHub

  1. Intri pe github.com și apeși Sign up. Folosește o adresă de e-mail la care ai acces și confirmă mesajul primit.
  2. Alege un nume de utilizator care să te identifice și pe care să nu-ți fie rușine să-l ai într-un CV — rămâne public și îl folosești tot semestrul.

Pasul 2 — Copia ta după repository (fork)

  1. Deschizi github.com/Programarea-Aplicatiilor-WEB/Laboratoare.
  2. Apeși butonul Fork (dreapta sus) → Create fork.

Primești o copie identică a repository-ului, în contul tău. Acolo lucrezi. Repository-ul laboratorului rămâne neatins până când predai lucrarea și este acceptată.

Pasul 3 — Încarci fișierele lucrării

Structura de foldere este fixă și trebuie respectată exact:

Lab1/<grupa>/<nume-prenume>/index.html
Lab1/1341a/popescu-ana/index.html      ← exemplu
  1. În copia ta, intri în folderul laboratorului și apoi în cel al grupei tale, de exemplu Lab1/1341a.
  2. Apeși Add file → Upload files și tragi cu mouse-ul folderul lucrării tale (numit nume-prenume) peste zona de încărcare. Subfolderele se păstrează așa cum sunt.
  3. Dacă preferi să scrii fișierul direct în browser: Add file → Create new file, iar în câmpul de nume scrii calea completă, Lab1/1341a/popescu-ana/index.html. Fiecare / creează un folder.
  4. Jos, la Commit changes, scrii o descriere scurtă — „Laborator 1 – Popescu Ana, 1341A” — și confirmi.
Ca să modifici ceva mai târziu: deschizi fișierul în copia ta și apeși pictograma creion (Edit this file), apoi Commit changes. Pentru modificări mai ample, din pagina repository-ului apeși tasta . (punct) și se deschide un editor complet în browser.

Pasul 4 — Îți pornești propria pagină web

  1. În copia ta: Settings → în meniul din stânga Pages.
  2. La Build and deployment → Source: alegi Deploy from a branch.
  3. La Branch alegi main, iar la folder lași / (root) → Save.
  4. După un minut, reîncarci pagina de Settings. Apare o bandă verde: „Your site is live at…”. De acolo se deschide site-ul tău, iar lucrarea ta este la:
https://<username-ul-tău>.github.io/Laboratoare/Lab1/1341a/nume-prenume/

Verifică la această adresă toate cerințele laboratorului: linkurile, căile relative între pagini, culorile, tabelul, imaginile. Ce nu funcționează aici nu funcționează nici la corectare — pagina care se vede corect doar pe calculatorul tău nu contează ca lucrare predată.

Pasul 5 — Predai lucrarea

  1. În copia ta apeși Contribute → Open pull request → Create pull request.
  2. În titlu scrii laboratorul, numele și grupa: „Lab 1 – Popescu Ana – 1341A”.
  3. În descriere lipești adresa paginii tale, obținută la pasul 4.

Data și ora la care ai deschis cererea reprezintă data predării. Dacă primești observații, corectezi fișierele în copia ta și dai din nou Commit changes: cererea se actualizează singură, nu trebuie să trimiți alta.

Metodologie de lucru

Ce conține o lucrare predată

  • Toate fișierele cerute în fișa laboratorului, într-un singur folder cu numele tău.
  • O pagină principală numită index.html, din care se poate ajunge la celelalte pagini ale lucrării.
  • Fișierele auxiliare — imagini, fișiere CSS — încărcate în același folder, cu căi relative corecte.

Denumiri

  • Litere mici, fără spații și fără diacritice: popescu-ana, nu Popescu Ana.
  • Adresele web fac diferența între litere mari și mici: Pagina1.html și pagina1.html sunt două fișiere diferite.
  • Folderul tău păstrează același nume tot semestrul, în toate laboratoarele.

Termene

  • Lucrarea se predă până la începutul laboratorului următor.
  • Ce încarci după termen rămâne vizibil ca modificare ulterioară, cu data ei — istoricul este public și nu poate fi rescris discret.
  • O lucrare respinsă se poate reface: corectezi în copia ta, iar cererea deja deschisă se actualizează automat.

Evaluare

  • Se evaluează pagina publicată, nu codul de pe calculatorul tău.
  • Observațiile le primești direct pe linia de cod, în pull request; le vezi în tabul Files changed și primești notificare pe e-mail.
  • Punctajul fiecărei lucrări este anunțat la laborator, odată cu cerințele.

Lucrare proprie

Lucrarea o scrii tu. Poți discuta soluții cu colegii și poți folosi documentația, dar codul predat trebuie să fie al tău și trebuie să poți explica orice linie din el. Istoricul modificărilor este public: se vede când și cum a apărut fiecare bucată de cod.

Probleme frecvente

Ce veziCe înseamnă și ce faci
Site not found GitHub Pages nu este activat pe copia ta sau ai greșit adresa. Reia pasul 4 și verifică numele de utilizator din adresă.
404 File not found Nu există niciun fișier la calea cerută: fie pagina nu se numește index.html, fie ai încărcat-o în alt folder, fie ai greșit majusculele.
Vezi pagina veche Publicarea durează până la un minut după commit. Reîncarcă forțat cu Ctrl+F5 (Cmd+Shift+R pe Mac).
Stilurile nu se aplică Fișierul CSS nu a fost încărcat sau calea din <link> nu corespunde structurii de foldere de pe server.
Imaginea nu apare Imaginea nu a fost încărcată în folderul tău sau numele din <img src> diferă prin majuscule ori prin extensie.
Linkul dintre pagini nu merge Folosește căi relative: L1/pagina1.html pentru o pagină dintr-un subfolder, ../index.html pentru una cu un nivel mai sus. Calea de pe calculatorul tău (C:\…) nu funcționează pe server.
